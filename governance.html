The trust boundary

The agent runtime requests an action. The verifier runs as a separate service with a separate database principal, provider credential and signing key. The runtime cannot mint a valid verifier receipt for itself.

Supported side effects bind the exact canonical action, idempotency key and provider receipt. Invalid or inconsistent evidence is rejected instead of being promoted to business truth.

What is deliberately excluded

  • No autonomous mission controller.
  • No self-improvement service.
  • No autonomous code deployment.
  • No browser worker or local desktop agent.

The customer-facing profile is the governance subset, not the autonomous Synthetic Time system.

Why the verifier exists

In Synthetic Time's own production history, provider responses were rejected when their payload digest did not match the verifier's canonical contract. The system did not convert unverifiable responses into accepted evidence. That failure mode is intentional: unsupported truth stays untrusted.
